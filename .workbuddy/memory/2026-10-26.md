## Next.js 前端第一阶段：首页 + 技能库跑通真实后端

### 新增
- `scripts/serve-api.mjs`：后端独立 API 服务（`npm run api`，默认 :8787，读根 `.env`）。
  动态 import `src/server/api/routes.ts` 的 `dispatchApi` + `rootRoutes.ts` 的 `dispatchRoot`，
  Node HTTP ↔ Web Request/Response 桥接。**后端源码零改动**。

- `web/src/hooks/use-skills.ts`：`useSkillsInfinite` 加两道护栏（去重 + 空页即停）。

### 真实后端方言（原先 Next 版是按另一套 Swagger 写的，整体对不上）
- 成功响应**无 `Resp` 包装**，payload 本身即 body；错误靠 HTTP 状态码
- 列表是**游标**分页：`cursor` + `limit` → `{ data, nextCursor }`（公开列表**不返回 total**）
- 内容类型字段 `type`：`skill` / `knowledge_base`（UI 侧叫 `knowledge`）
- 上下架字段 `listing`（listed/unlisted）；**没有** visibility / moderationStatus
- 密码**明文**（服务端 scrypt）；原先的 AES 预处理（`lib/crypto.ts`）已从适配层移除
- 排序只有 created/downloads/stars/updated/name——UI 的 `hot` 要映射成 `downloads`
- 端点差异：分类走 `/api/v1/categories/in-use`；上下架走 `POST /admin/skills/:slug/listing`；
  重置密码走 `POST /admin/users/password`；审计筛选参数是 `resource_type`；
  `/api/v1/brands`、`/api/v1/email-code`、`/api/v1/admin/audit-actions`、`.../review` **后端没有**

### 代理配置
- `web/next.config.ts`：`/skillhubservice/:path*` → `${API_PROXY_TARGET}/:path*`（**剥前缀**，后端只认 `/api/**`）
- `web/.env.development`：`API_PROXY_TARGET=http://localhost:8787`、`NEXT_PUBLIC_API_BASE_URL=/skillhubservice`
  （原文件指向测试环境 SIT，已改成本地）

### 顺带修掉的后端游标 bug（`src/server/repo/skills.ts`）
原比较 `(s.col, s.id) < (c.col, c.id)` 与 `ORDER BY s.created_at DESC, s.id`（tiebreaker 是 ASC）方向不一致。
批量 seed 的 38 个内置技能 **created_at 完全相同** ⇒ 第 2 页原样返回第 1 页，
React 报 12 个 duplicate key，且 26 个技能永远刷不出来。
改成 `(s.col <op> c.col) OR (s.col = c.col AND s.id >= c.id)`（`<op>` 随排序方向；id 用 `>=` 是因为
游标停在本页**没返回的第一行**上，那一行属于下一页）。这是本次唯一的后端源码改动（不动 schema / 迁移）。

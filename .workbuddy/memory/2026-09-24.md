## 管理端 API Key（新增能力）

给 admin 加了 API Key 管理：页面 `/admin/api-keys`，后端 `GET/POST /api/v1/admin/api-keys` +
`DELETE /api/v1/admin/api-keys/:id`。

**定下的三个取舍（用户选的）**：独立表 + 独立前缀、按接口收窄权限、可选绑定命名空间。

- 存储：`api_keys` 表（migration v4，不是改 api_tokens），key 形如 `shk_`（`SKILLHUB_API_KEY_PREFIX`，
  默认 `shk_`，与 `clh_` 个人 token 区分）。只存 sha256 + 16 字符展示前缀，明文只在创建时返回一次。
- 认证：`http.ts` 的 `resolveIdentity` 按前缀分流（`isApiKey`），key 认证得到的是**签发者**身份，
  但要求签发者仍是 admin 且未被封禁——降级/封禁即失效。key 绑定的 namespace 走 `tokenNamespaceId`，
  publish 因此自动落在该 ns 且不能发到别处（403）。
- 权限：新增 `ApiKeyScope = skills:read | skills:publish | skills:delete | skills:moderate`，
  `RouteDef.apiKeyScope` 逐路由标注（K_READ/K_PUBLISH/K_DELETE/K_MODERATE 四个常量），
  **未标注的路由一律拒绝 key**（403 "this API key is not allowed for this endpoint"），
  所以 key 只能管技能，碰不到用户/插件/命名空间接口。检查点在 dispatch 里、认证之后。
- 服务层 `src/server/services/apiKeys.ts`（创建/列表/撤销 + 审计 admin_create_api_key /
  admin_revoke_api_key），SQL 只在 `src/server/repo/apiKeys.ts`。
- 页面双语、权限用可勾选卡片（复用 `.admin-feature-item`），撤销有 confirm。

## 踩到的坑

- smoke 里"过期/撤销 key → 401"最初断言在 `GET /api/v1/skills` 上，那是 `auth: 'optional'`，
  凭据失效会退化成匿名并正常 200。**测死凭据要用 `auth: 'required'` 的路由（whoami）**。
- `skillSvc.undelete` 用 `resolveSkillRef` 不带 `includeDeleted`，软删后 undelete 永远 404。
  这是原实现行为，**不要顺手改**，断言别依赖它。
- agent-browser 的 `click @ref` 在 React 受控表单上有时点不动（按钮刚从 disabled 变 enabled）；
  用 `agent-browser eval "…button.click()"` 更可靠。

## 本轮的坑

- **别在源码里写控制字符字面量**：正则字符类写成真实控制字符会让文件变"二进制"，
  grep 直接报 Binary file matches。要写 `\u0000-\u0020` 这种转义形式。
- Node 的 `--experimental-strip-types` 只 strip `.ts`；`.mjs` 里写 TS 注解会报
  "Missing initializer"。临时验证脚本用 `.ts` 后缀。
- zsh 下 `rm -f /tmp/foo.db*` 无匹配会直接中止整条命令（nomatch），后台起服务会静默失败。

## 踩坑：curl 上传文件名

`-F "files=@/tmp/SKILLDEMO.md"` 会以 **本地文件名** 作为存档内路径，于是技能里根本没 SKILL.md，
详情页显示 "Unable to read..."。差点把它误当成"二选一生效"的证据。
正确写法：`-F "files=@/tmp/SKILLDEMO.md;filename=SKILL.md"`。

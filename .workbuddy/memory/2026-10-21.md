## 排查「复制 API 功能说明是否覆盖知识库」+ 修掉发布接口的 manifest 漏洞

用户问：管理页复制 API 功能的说明是否有更新知识库相关的？

**已有**（提交 `7b0821e` + 上一段会话未提交改动）：新增两条示例
「按类型筛选（技能 / 知识库）」「发布知识库」；`skills:publish` 权限说明已含知识库；
页面副标题与空状态已改「管理技能与知识库」。
**缺口**：`skills:read` / `skills:delete` / `skills:moderate` 三条权限说明仍只写「技能」。

**但查出真 bug**：那条「发布知识库」curl 示例**没有任何文件参数**，实测跑通后
版本里 **0 个文件** ⇒ 下载 404（`create archive: no files in version`）、详情页无内容可渲染。
根因：上一轮只在**控制台表单**路径（`createSkillFromForm`）为知识库合成 manifest，
**发布接口**路径（`POST /api/v1/skills` → `publishVersion`）没合成 ⇒ 两条写入路径不一致。

**修法（收敛到一处）**：
- `services/skills.ts` 新增导出 `stubSkillMd({displayName, summary, slug})`；
  `publishVersion` 里 **`type === 'knowledge_base' && !files.has('SKILL.md')` 时合成一份**
  （新增校验步骤 6「files」，后续步骤顺延；commit 块的指纹/落库/`parsed` 全改用合成后的 `files`）。
  ⚠️ 上一轮的步骤编号本来就有 **#7 重复、#8 缺失**，这次又叠加出一层重复 #10，已按文件顺序重排成 1–15。
- `services/manage.ts` 删掉自己那份 `skillMdStub` 实现与两处 KB 合成逻辑，改为 import 共享的
  `stubSkillMd`（原来本地还有个同名 `stubSkillMd` 会 shadow import，已删）。
- 示例改为带 `-F "files=@<package>"`（更真实）；三条权限说明补上知识库。
- ⚠️ 技能路径**行为不变**：API 发布技能仍是「给什么存什么」，不会凭空造文件
  （smoke 有 `smoke-skill-api` 反向断言钉住）。

**验证**：typecheck 0 错 → build → smoke **375 条全绿**（新增 16 条，其中 6 条正是
`POST /api/v1/skills` + `type=knowledge_base` 这条此前**完全没覆盖**的路径）。
隔离库实测：旧示例（无文件）现在也能下载、有 SKILL.md；新示例（带包）两个文件都在。
浏览器实测：示例渲染、权限说明文案、复制出的纯文本说明（拦截 `writeText` 捕获）
都含两条知识库示例。

**教训**：放宽某个约束时，**每条写入路径都要过一遍**。这次只改了控制台，
API 路径就留下了「能创建但不能下载」的条目。示例代码（curl 样例）属于交付物，
要当代码一样跑一遍——它当时是坏的。

# 2026-10-22

## 修复：下载包混入「简介合成的 SKILL.md」

**用户反馈**：上传附件后下载，压缩包里多出一份把「简介」当正文的 `SKILL.md`。
下载的压缩包应该就是上传的附件本身。

**根因**：上一轮（2026-10-21，commit d8c9b3e）为让「空知识库可下载」在
`publishVersion` 步骤 6 给每个缺 manifest 的知识库上传合成了一份 `SKILL.md`
存根并**落库**，于是上传了资料的知识库，版本里也永远带着这份简介存根，
下载包 = 上传附件 + 合成说明文件。

**改法**（合成内容不是发布者内容，不进交付物）：
- `services/skills.ts` `publishVersion` 步骤 6：只在 `req.files.size === 0`
  （一个文件都没上传）时合成 manifest；有上传就原样存。
- 新增导出 `isSynthesizedStub(skill, content)`（逐字节等于当前元数据算出的存根），
  `mergedVersionFiles`（控制台编辑上传）与 `updateFile`（`PUT .../file` 单文件写）
  都用它把合成存根挡在新版本之外——三条「文件进入版本」的路径全过一遍。
- `routes/skills/$.tsx`：详情页回落链补最后一环——无富文本正文且 `SKILL.md`
  读取 404（包裡没有 manifest）时展示简介，不再弹错误框；真读取失败仍报错。
- smoke：重写 2 条钉住旧行为的断言，新增 12 条（下载包条目名用 `zipEntryNames()`
  走 ZIP 本地头解析，`downloadEntries()` 封装）；smoke-kb-merge / smoke-kb-file
  两个夹具钉住「先空创、后上传/单文件写」的合并不继承存根。断言总数 375 → **387**。

**验证**：typecheck 0 报错；build；smoke 387/0；另写临时复现脚本
（临时库 + 真实 HTTP）确认三种情形：有上传→zip 就是附件；API 发布同理；
完全没上传→仍下载到合成 manifest。浏览器验证详情页两态（无 manifest 展示简介 /
有富文本展示正文）。

**注意**：历史已发布版本内容不可变，之前被污染的版本仍带存根；对这些条目
重新上传资料（编辑保存）即生成干净的新版本（元数据没变时存根会被识别并丢弃）。

## 追加：上传单个 zip 时下载原样返回该 zip

**用户追加要求**：上传的是一个 zip 包就不用二次压缩，直接下载这个 zip。

- `services/skills.ts` 新增导出 `uploadedZip(files)`：版本**只有这一个 `.zip`** 时
  返回 `{name, content}`；`download()` 与 agent `archive()` 都改走它，不再
  `createZip` 包一层（否则用户要解压两次）。多文件（含 zip 混在其中）照旧打成一个包。
- 下载文件名用上传时的名字；`DownloadResult` 加可选 `fileName`。
- ⚠️ **踩坑**：中文文件名直接插进 `Content-Disposition` 会让 `new Response` 抛
  `Cannot convert argument to a ByteString…`，整个下载变 404。新增
  `http.ts` 的 `contentDisposition(name, fallback)`：ASCII 名维持原样，
  非 ASCII 名走 RFC 5987 `filename*=UTF-8''…` + ASCII 回落名。
- smoke：新增 `makeZip()`（store-only、自带 CRC32，不依赖系统 zip 命令）与
  `downloadRaw()`；断言下载字节与上传字节 sha256 相同、解压出来是 zip 内部
  文件而非又一层 zip、保留上传文件名、中文名走 5987、多文件仍打成一个包。
  断言总数 387 → **399**。
- 验证：typecheck 0 / build / smoke 399-0；另跑真实 zip（系统 zip 命令生成）
  端到端 demo：上传 503 字节 zip → 下载 503 字节、sha256 一致、解压即内部文件。

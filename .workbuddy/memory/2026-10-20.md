## 技能表新增「类型」：技能 / 知识库

用户需求：给技能表加一个类型（技能/知识库），在上传面板和 API 加区分，其他选项一样
（写介绍 + 上传包），首页 header 多一个「知识库」入口，页面单独列知识库，
首页精选拆成「精选技能 / 精选知识库」。

四项产品决策（已与用户确认）：
1. `/skills` 与 `/knowledge-bases` **完全分开**，互不重叠
2. 首页「热门」也拆成热门技能 / 热门知识库两块
3. 精选**是同一个池子按 type 分流**（后台仍只有一个「首页精选」清单，管理端不用改）
4. 搜索**混排返回、不加类型过滤**（卡片靠角标区分）

### 实现

- **迁移 v15**：`skills.type TEXT NOT NULL DEFAULT 'skill' CHECK (type IN ('skill','knowledge_base'))`
  + `idx_skills_type`。append-only，没动 v1 的 `INITIAL_SCHEMA`。
- **FTS5 索引没动**：搜索混排 ⇒ 不需要索引列。搜索结果的类型从 `HIT_SELECT` 的
  `LEFT JOIN skills s` 读（`COALESCE(s.type,'skill') AS s_type`），FTS 路径与 LIKE 回落路径都加了。
- **写路径**：`checkedType`（空 = skill，非法 = 400）；控制台表单 `type` 缺省 skill；
  发布 API `type` 空串 = 不改已有条目；`publishVersion` 只在新建时定类型。
- **读路径** `?type=skill|knowledge_base`（不传 = 两种都返回）：`/api/v1/skills`、
  `/api/v1/namespaces/:slug/skills`、`/api/v1/features`、`/api/v1/categories/in-use`、
  `/api/v1/admin/skills`。
- **SKILL.md 规则按类型分**（唯一的行为差异）：skill 必须带（缺 → 400）；
  knowledge_base 不必带（简介在富文本正文里），服务端用表单合成一份 manifest 补上
  （`stubSkillMd`），保证页面回落与下载包都还有 SKILL.md。
- **runtime API 排除知识库**（`type='skill'`）：那是给智能体运行时加载可执行技能的。
- **agent API 的 `type` 字段是 `kind` 小写**（既有发布契约），没动。

### 顺带修掉的卡片布局 bug（被角标触发）

加「知识库」角标后卡片变挤，窄列（3 列网格）里**中文标题被压成一字一行**：
`.card-head .card-title { flex: 1; min-width: 0 }` 允许标题缩到内容宽度以下，
而 CJK 可以在任意位置断行 ⇒ 标题塌成竖排；同时 `.card { height: 200px }` 固定高度把摘要切掉。
改法：
- `.card-head` 加 `flex-wrap: wrap`，标题 `flex: 1 1 8em; min-width: 8em`（不再塌），
  `.card-tags` 从 `flex-shrink: 0` 改成 `flex: 0 1 auto`（可换行）
- `.card { height: 200px }` → **`min-height: 200px`**，并让 `.skill-grid a { display: flex }`
  ⇒ 卡片撑满网格单元，**同一行所有卡片底边仍然对齐**（grid 默认 stretch）
- 角标占掉一个标签位：带角标的卡片只显示 **2 个**标签（总共仍是 3 个 chip），chip 行不换行

实测：卡片高度仍 200px，标题 1 行或 2 行，摘要完整不裁切。

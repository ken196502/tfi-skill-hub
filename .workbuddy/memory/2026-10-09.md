### 踩坑
- 用 Edit 写正则时，字面控制字符范围（`[\x00-\x1f]` 这种）被当真实字符写进了源码，
  文件变 binary，grep 报 "Binary file matches"。**一律用 `/[\u0000-\u001f\u007f]/g` 显式转义。**
  同样的原因，用 `cat > file <<'EOF'` 写含控制字符的记忆文件也会静默失败 —— 改用 Write 工具。
- `formFields` 从 `Map` 改成 `{get, all}` 后，原有 `fields.get(x) ?? ''` 与 `?? undefined`
  都还正确（`''` 是 falsy），但改动前要逐个确认，别默认。
- 迁移状态记录在 `PRAGMA user_version`，**不是** `schema_migrations` 表 —— 查迁移别找错地方。
- `agent-browser click <ref>` 点 `.reg-chip` 会假失败（坐标没命中），但 `aria-pressed` 证明
  React 逻辑正常；用 `eval` 里 `el.click()` 才是可靠验证路径。
- Bash 工具每次调用是独立进程，后台起的服务会在命令结束时被回收 —— 要长期存活必须用
  `run_in_background: true`，再用 TaskStop 收尾。

## 审核结果锁定：approved 是终态（同日追加）

需求：「审核通过之后不能再驳回」。原本只有前端按钮 disabled，**服务端 `reviewUser` 完全不看
当前状态** —— 直接打 `POST /api/v1/admin/users/review` 就能把一个已在使用的账号改成 rejected，
用户立刻掉线，且登录页会显示不实的「注册未通过」。

规则（已与用户确认）：
- `approved` 是**终态**，不能再转 rejected。收回访问权走 `banUser`（有独立原因字段和审计动作）。
- `rejected → approved` **允许**（申请人补资料后二次审核通过）。
- 重复同一个决定 = **幂等空操作**，直接 return，不报错也不重复写审计（防双击/重试）。

改动：
- `services/manage.ts` `reviewUser`：加守卫。`approved + reject` → `fail('this account has already
  been approved; use ban to revoke access')`；`target.status === next` → 提前 return。
- `admin.users.tsx`：驳回按钮 disabled 条件加 `|| item.status === 'approved'`；三个按钮都补
  `title` 说明为什么灰（原来灰按钮无解释，审核人会困惑）。
- 新增 `friendlyReviewError()`：服务端英文报错在界面用 `t()` 复述，不直接抛英文原文；
  未识别的消息仍原样显示，不吞错。

### ⚠️ 顺带发现的缺口（已告知用户，未修）
**`/admin/users/ban` 只接受 `reason`，没有 `banned: false` 分支 ⇒ 封禁之后无法解封。**
`manage.ts` 里 `users.setBanned(id, true, reason)` 写死 `true`，repo 没有 unban 入口。
既然现在把封禁确立为「收回访问权的唯一途径」，误封就找不回来了 —— 需要补解封能力。

### 验证
- typecheck / build / smoke 全绿（**301 断言**，新增 7 条）
- 新断言：驳回已通过 → 400 且指向 ban；被拒后账号仍能登录、仍是 approved；重复 approve → 200
  幂等且不重复写审计；封禁已通过账号 → 200 且封禁后登不进、审批记录不变
- 真实 HTTP 复核：approve → reject 得 400 + 账号照常登录；rejected → 重复 reject → 补批 approve
  全部符合预期；浏览器确认已通过账号的「通过/驳回」双灰、「封禁」可用

### 冒烟脚本写法
`applicant()` 工厂造完整合法载荷（注册）；审核侧则是「先 reject 再 approve 走完补批路径」，
再单独断言 approved 后的三条边界。别在同一个账号上堆太多状态，断言会互相干扰。

## 地区字段改为可搜索下拉（同日追加）

需求：「所在国家或地区」要同时支持输入关键字搜索和下拉。原生 `<select>` 只能二选一，34 项
滚动找太慢 ⇒ 换成 combobox。

### 改动
- **新增 `src/components/Combobox.tsx`**：通用可搜索下拉，不是注册页专用。
  按 ARIA combobox 模式实现 —— 焦点始终留在输入框，用 `aria-activedescendant` 指向高亮项，
  这样打字能继续过滤。键盘：↑↓ 移动（首尾环绕）、Enter/Tab 提交、Esc 放弃输入并还原已选标签、
  blur 时若输入与某项完全匹配则提交。
- **两个关键实现细节**（写错了会出 bug）：
  - 选项的 `onMouseDown` 而不是 `onClick`：mousedown 先于 input 的 blur 触发，
    用 click 会被 blur handler 把 filter 回滚成旧选择，导致点不中。
  - `closingRef` 标记 Escape/mousedown 已处理，blur 里判一下就 return，否则关闭动作会被
    blur 的「提交或还原」逻辑覆盖。
  - `document` 上监听 **pointerdown**（不是 click）判点击外部，否则点另一个选项时
    会先触发"关闭"再触发"打开"。
- **`lib/registration.ts` 新增 `countryOptions(lang)`**：把 COUNTRIES 转成 combobox 行，
  `keywords` 塞**另一种语言 + ISO code** ⇒ 中文界面搜 "Japan" 能命中日本、搜 "SG" 能命中新加坡。
- `RegisterPage`：`<select>` 换成 `<Combobox>`；`useLang()` 取 lang、`useMemo` 固定
  `countryOptions(lang)`（每次渲染新建数组会让 combobox 的 filter memo 失效）。
- `global.css`：`.combo*` 一组。浮层 `z-index: 30` 盖住下方字段，不给表单预留高度。
  已选项高亮不能只靠颜色（键盘也在驱动），所以 active 有背景色、selected 有字重。

### 验证
- typecheck / build / smoke 全绿（301 断言，无回归 —— 纯前端改动，没动服务端）
- 浏览器逐项实测：聚焦展开 32 项；中文搜「香港」→ 中国香港；中文界面搜 "Japan" → 日本；
  搜 "SG" → 新加坡；搜「瑞」→ 瑞士+瑞典两项，ArrowDown 移动高亮、Enter 提交「瑞典」；
  Escape 还原空值；无匹配显示提示文案；重开列表时已选项带 selected 标记；清除按钮清空并
  保持焦点；完整注册走通且 country 落库为 `SG`（不是中文标签）。

### 踩坑
- `agent-browser eval` 里 `const x = ...` 会在 daemon 全局残留作用域，下一条 eval 报
  `Identifier 'x' has already been declared`。**每次 eval 用不同变量名或包在 IIFE 里**，
  交互优先用 `agent-browser type` / `press` 真实事件（中文输入也可靠）。

## 邮箱验证码（固定 123456，同日追加）

### 文案决策（重要）
**界面上不出现「演示 / 固定验证码 / 未接入邮件服务」等说明** —— 按用户强约束，那是给
看代码的人看的，不是给用系统的人看的。界面只写正常产品口吻：「邮箱验证码」「6 位数字」
「请输入邮箱收到的验证码」。**`123456` 写进两份产品文档**（`docs/product-guide.md` +

  要换成一次性、限时、按地址签发的码。

## 生产库能不能「重建 users 表」的查证（2026-10-08）

用户问「生产 user 表没有新用户、只有初始化内容，如何重建」。先做只读盘点（`GET https://skills.subx.fun/api/v1/skills?limit=100`）：

- **公开技能 22 个，全部在 `admin` 命名空间、`admin` 名下**（us-stock-pick-agent / investment-system / …）——
  所以「只有初始化内容」对 **users 表**成立（只有 `admin` 与 `skillhub` 两个内置账号），
  对**整个库不成立**：这 22 个是用户内容，且 owner 就是 `admin`。
- 由此得出关键警告：`users` 是父表，`namespaces/skills/api_tokens/...` 都是 `REFERENCES users(id) ON DELETE CASCADE`。
  在**外键开启**的情况下 `DELETE FROM users` / `DROP TABLE users` 会**级联删掉这 22 个技能及其版本/文件/搜索索引**。
- 结论：**不需要重建这张表**。v7/v8 迁移在服务启动时自动跑，老账号不受影响；重建的唯一收益只是让
  `role` 的 CHECK 也拒绝 `'moderator'`（功能上无差别，写入侧已强制）。

顺带查到的部署细节（写指令前必须注意）：
- **`scripts/create-admin.mjs` 不在镜像里**：Dockerfile 只 COPY 了 `dist/` 和 `scripts/serve.mjs`。
  所以要在生产改口令，得先 `docker compose cp scripts/create-admin.mjs skillhub:/app/scripts/` 再 `exec`。
- 生产数据在命名卷 `skillhub-data`（容器内 `/app/data/skillhub.db`），备份要连 `-wal` / `-shm` 一起拿。
  宿主机路径：`/var/lib/docker/volumes/tfi-skill-hub_skillhub-data/_data/skillhub.db`。

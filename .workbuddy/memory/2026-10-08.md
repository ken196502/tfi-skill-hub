## 「管理员账号密码被预填」排查（2026-10-08）— 结论：浏览器自动填充，非代码问题，未改代码

用户报「登录页管理员的账号密码是填好的」。逐层排查后确认**项目源码/构建产物/线上都没有预填**：
- `src/components/LoginPage.tsx` 两个输入框初始值均为空串（`useState('')`），全仓库无 `admin` / `admin12345` 之类的预置值；
- 线上 `https://skills.subx.fun/login` SSR 输出为 `<input ... value=""/>`；
- `dist/client/assets/login-*.js`、`dist/server/...` 均无硬编码凭据。

判定为**浏览器保存密码后的自动填充**（表单用了 `autoComplete="username"` / `"current-password"`）。
用户确认「应该是浏览器记住了，没问题」，**因此不做改动**。

## 管理员凭据改为从 .env 注入（2026-10-08，已交付）

用户要求把写死的默认管理员口令改成从 `.env` 注入。改动 4 个文件：

1. `docker-compose.yml` —— 原来 L43-44 写死 `admin` / `admin12345`，改为
   `${SKILLHUB_ADMIN_USER:?请在 .env 中设置…}` / `${SKILLHUB_ADMIN_PASSWORD:?…}`。
   用 `:?` 而非 `:-`，缺值或空值都直接报错退出，不给任何回退默认。
2. `package.json` —— `start` 原为 `node dist/server/server.js`，**该文件只导出 Web handler、
   不监听端口，直接跑会立刻退出（实测 EXIT=0、healthz 连不上）**；改为
   `node --env-file-if-exists=.env scripts/serve.mjs`，与本仓库 Dockerfile 注释、
   `scripts/smoke-api.mjs`（spawn 的就是 serve.mjs）一致。生产容器走 docker-entrypoint →
   serve.mjs + compose 注入环境变量，不受此改动影响。
3. `.env`（不入库）—— 补 `SKILLHUB_ADMIN_USER=admin` + 新生成的 24 位强口令；原有 PAT 行保留。
4. `.env.example`（新增、入库）+ `README.md`（快速开始去掉 `admin12345`，配置表补必填说明）。

验证（本机无 docker，用等价方式）：
- 端到端：`npm start` 用临时库起服务 → healthz 200；用 `.env` 里的新口令 `POST /login` = 200；
  用旧默认口令 `admin12345` = **401**（确认没有默认凭据路径残留）。
- compose：用 `node_modules/js-yaml` 解析 YAML + 按 `${VAR:?msg}` 规则模拟替换 →
  有 `.env` 时解析出真实值、无 `.env` 时按预期直接失败（`/tmp/compose-check.cjs`）。

## 新增：注册 + 管理员审核 + 下载需登录 + 管理员标识（2026-10-08，已交付）

四个需求一次做完，四个设计取舍先用 AskUserQuestion 敲定（都取了推荐项）：
待审用户**不能登录**；只有**打包下载**需登录；**新增 `users:moderate`** scope；注册**公开+开关**。

改动清单（沿用四层结构：schema → repo → service → handler/route，前端另算）：
- `schema.ts` migration **v7**：`users.status`（`pending|approved|rejected`，NOT NULL DEFAULT 'approved'，
  带 CHECK）+ `review_note`/`reviewed_at`/`reviewed_by` + `idx_users_status`。
  实测 SQLite 允许 `ALTER TABLE ADD COLUMN ... NOT NULL DEFAULT ... CHECK(...)`，存量行自动 'approved'。
- `lib/types.ts`：`UserStatus`、`User.status`（必填）+ review 三字段（可选）、`ApiKeyScope` 加 `users:moderate`。
- `repo/core.ts`：mapUser 补 status/review 字段；`users.create` 支持 status；新增 `users.review()`；
  `users.list(cursor,limit,status?)` 支持状态过滤；新增 `countByStatus`。
- `config.ts`：`SKILLHUB_ALLOW_REGISTRATION`（envBool，默认开）。
- `services/manage.ts`：`registerUser()`（handle 正则 2–32 位、密码≥8、查重、写 audit `register_user`）、
  `reviewUser()`（approve/reject + audit `review_user_{approve,reject}`）、`listUsers` 带 status 过滤并回传 `pendingCount`。
- `http.ts`：`authenticateToken` / `authenticateApiKey` 都加 `status !== 'approved' ⇒ ANONYMOUS`（待审账号无会话）。
- `handlers.ts`：`auth.register`、`auth.registrationStatus`、`admin.reviewUser`；`login` 在**密码校验通过之后**
  才按 pending/rejected 报 403，并带 `code: 'account_pending' | 'account_rejected'`（新增字段，
  与歧义 slug 的 `candidates` 同类，属可加性扩展，避免前端匹配英文文案）。
- `routes.ts`：加 `K_USER`（users:moderate）常量；`POST /register`、`GET /api/v1/registration`（public）；
  `GET /admin/users` + `POST /admin/users/review` 标 `K_USER`；**打包下载改 `auth:'required'`**：
  `/api/v1/download`、`/api/v1/plugins/download`、`/api/runtime/skills/bundle`（单文件读取仍公开）。
- 前端：新增 `components/RegisterPage.tsx` + `routes/register.tsx`（POST handler 仿 login.tsx）；
  LoginPage 加注册入口 + 403 按 code 提示；`lib/auth.tsx` 加 `useRegistrationOpen()`；
  `admin.users.tsx` 加状态列/状态筛选/通过/驳回（驳回带理由）/待审提示条；
  `Layout.tsx` 右上角加 `.nav-role-chip`（管理员/审核员）；`admin.api-keys.tsx` 补 scope 文案与示例；
  `admin.audit-logs.tsx` 补 3 个 action 标签；技能详情页未登录时下载按钮改为「登录后下载」。

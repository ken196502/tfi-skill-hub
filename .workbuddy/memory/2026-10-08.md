## 权限审计：普通用户实际能做什么（实测，未改代码）
- 探针 `/tmp/perm-probe.mjs`：临时库 + 真实 HTTP，注册普通账号 → admin 审核通过 → 登录 → 逐个打写/管理接口。
  结论：**admin 面是严的，但「发布 / 命名空间 / token」没锁** —— 与用户口径不一致，待决策。
- **已正确挡住**：`/api/v1/admin/*` 全部 15 个探针 → 403 `insufficient permissions`（靠路由 `auth:'admin'`，
  会话与 API key 都过不去）；改/删/转移/撤回/弃用**别人的**技能 → 403（`authorizeSkillWrite`）；
  `POST /api/v1/agent/provision` → 404（`SKILLHUB_AGENT_SECRET` 未设即 notFound）；
  管理页还有 `AdminGuard` 客户端兜底。
- **越权（普通用户 ALLOWED）**：①`POST /api/v1/skills`→200、`POST /api/v1/plugins`→201
  （都落到 `ensurePersonalNamespace` 自动建的个人命名空间）；②`POST /api/agent/skills`→201（第二条发布通道）；
  ③`POST /api/v1/namespaces`→201、`GET /api/v1/namespaces`→200（还能管自己命名空间的成员/邀请/团队 token）；
  ④`POST /api/v1/tokens`→201 可签 `scope=full` 个人 token，且**个人 token 的 `scope` 全项目无人读取**
  （`http.ts` 把 `tokenScope` 塞进 ctx，没有任何消费点）⇒ scope 形同虚设；⑤评分/评论 → 200。
- **前端**：普通用户导航只有 技能/收藏/登录（管理仅 admin 可见）；`/publish`、`/namespaces` 是**孤儿路由**
  （导航无入口），但 `/publish` 直接敲 URL 就能正常发文；个人 token 无任何 UI。
- 状态码口径提醒：`purge` 400 `admin required`、`request-public` 400 `forbidden` —— **已是拒绝**，
  只是 `fail()` 被映射成 400（项目契约如此，不是漏洞）。
